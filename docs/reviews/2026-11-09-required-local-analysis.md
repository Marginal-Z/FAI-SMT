# 本地语言模型必经流程与紧凑布局验证

目标版本：3.3.0（4030）。

## 行为

本地模式内部先解析、生成配对草稿与硬性校验，再把全部草稿行交给语言模型逐项分析，包括一致项和单侧未匹配项。草稿不公开到结果页。每一行都必须收到有效 ID、判定和非空依据，全部完成后才设置最终报告、允许导出并保存历史。语言模型不能覆盖明确的数量、位号、字段冲突或不完整性问题；对原本一致的项可以独立提出复核。

使用 Qwen3-4B Q4_K_M；向量推理不计入本地模式完成条件，四种向量模型只作为混合模式的可选候选辅助。缺模型、加载/推理失败、超时、无效/漏答或取消均不回退成纯规则结果。批次不完整、截断或上下文不足时递归拆批，单行仍失败则整次失败。纯本地模式不追加云端总结请求。

SDK 原先的结构化辅助方法没有向调用方提供完成原因；当前直接收集原生流，要求正常 `stop` 结束，再进行 JSON Schema 与业务覆盖校验；`length` 截断不能作为有效回答。上下文使用实际模板 token 数预检。

上传卡片改为两行；触摸按钮保持 44 像素点击范围。独立方向提醒区块按元件类别汇总物料/位号，支持展开明细、点击定位、仅看需核方向。方向提醒不能代替实物检查。

## 验证边界

真实推理证据来自 Linux/WSL；Windows 与 Android 的原生模型加载和设备速度仍需各自硬件验证。完整演示通过说明运行流程和输出完整性有效，不构成大规模准确率测评。DeepSeek 协议回归来自可控服务器，未使用用户账号在线核对。本地模式仍使用程序做输入解析、配对草稿和硬约束，没有将整张 BOM 的全部匹配交给模型自由生成。

`full-setup.exe` 只带向量模型；本地模式需要另行下载 Qwen3-4B，避免把旧安装包描述成已具备语言分析能力。版本 3.2.x 的审查和截图记录只描述当时行为。
