# 核对页重排与自适应验证

目标版本：3.3.1（4031）。最终界面要求：取消圆角卡片，以直角、细边框和行分隔线组织信息。

## 发现与调整

旧界面在宽度不足 1250、可用高度不足 900 时采用另一组顶部布局，并给结果表格设置较大的固定高度，整页再滚动。上传卡片、操作卡片、六个大统计卡片、模型配置和方向明细连续堆叠，普通笔记本首屏留给结果的空间很少。结果列在最右侧，较窄窗口需要横向滚动后才能看到判定。

现在统一使用文件行和操作工具栏，压缩统计项，把模型与方向提醒整理为摘要。桌面顶部有独立滚动范围，筛选栏和结果区保留在窗口中；结果列位于料号旁。模型与方向摘要并列，方向明细在两者下方全宽展开，避免一侧展开后另一侧出现大块留白；明细按空间分为 1–3 列。展开不会把整个结果表推到页面下方。宽度不足 1000 的核对工作区使用物料清单及单页滚动，已导入文件和模型选项默认折叠，仍可展开修改。分析中同样收起次要配置，让进度和取消操作可见。

继续使用项目既有的语义颜色、现代/工业配色和三种语言，两种配色均统一为直角、无卡片阴影。统计项合并为连续表格栏，物料和方向明细以行分隔线区分；底部导航为全宽直栏，移除悬浮玻璃效果。布局按照可用约束及内容宽度重排。UI/UX 资料检索没有找到能直接应用于该 Flutter 工作台的信息分层条目，因此信息分层采用现有组件和实测约束；Flutter `LayoutBuilder` 指引与项目实际 API 验证后使用。

## 验证

`test/check_layout_test.dart` 覆盖常见笔记本、手机、平板和横屏小窗口，检查：

- 普通桌面窗口保留至少 240 像素的结果区，展开方向明细后仍保留结果区；方向摘要无需滚动顶部就可见。
- NG 判定无需横向滚动就能看到；调整窗口大小后筛选保持。
- 物料详情在笔记本尺寸下无布局异常。
- 手机分析中结果和导出仍不可用，进度的取消操作位于底部导航上方；取消后不输出结果。

完整测试 **165 项通过、9 项跳过**；跳过项缺少本机模型文件或客户样本，没有当作已验证。`flutter analyze --no-pub lib test tool` 无问题。覆盖模型选择、开关、自检入口、方向筛选、手机点击、新手引导和 80% / 150% 缩放；表格纵向与横向滚动位置、筛选在切换紧凑布局后均可恢复。中文、英文、泰文、深浅色、工业配色等共 **11 组实际渲染**通过，没有布局异常。

Linux x64 Release 构建通过；Xvfb 下窗口持续运行至 12 秒检查结束，没有崩溃。测试环境没有桌面密钥服务，出现 libsecret 提示，因此不将本次启动检查当作凭据存储验证。

复现核心检查，在 **WSL Ubuntu** 的项目目录执行：

```bash
flutter test --concurrency=1
flutter analyze lib test tool
flutter build linux --release
```
