# 阶段 11：误判修正、A/B/C 命名、可配置核对、多种本地模型、核对记录

日期：2026-11-08。起因是用户用真实文件（NG011 主板站位表 vs T100 BOM）核对：57 PASS、34 NG，几乎全是误判；结果表料号显示不全；低配置电脑跑不动本地模型；核对与输出固定死；没有历史记录。

## 误判：原因与修正

在用户的两份真实文件上逐条复现（客户文件只在本机读取，不进仓库）：

| 原因 | 条数 | 修正 |
| --- | --- | --- |
| 站位表「关联料号」列写的是本行自己的料号，T100 BOM 的替代料列为空，按「其他列必须完全一致」判了 NG | 33 | 替代料号按集合比较，去掉本行自己的料号；只有两边都登记了替代料且不同才提示（`alt_differs`），不影响结果 |
| T100 导出按固定宽度在单元格内换行，换在词中间（「13x1↵5mm」「沃尔↵玛」），读成「13x1 5mm」后与「13x15mm」比较不一致 | 1 | 读表时：换行两侧都是汉字，或长行（≥20 字符）中两侧都是数字或小写字母，视为固定宽度折行，直接拼接；其他换行仍变成空格。描述只差空白时视为相同 |
| BOM 上的锡膏、标签、碳带、PCB、组件行（用量 0 或小数）在站位表上本来就没有 | 6 | 未匹配时标注 `not_on_line`（辅料、包装、PCB 或组件行），风险降为低 |

结果：NG011 从 57 PASS / 34 NG 变为 91 PASS / 0 NG / 9 未匹配（3 条站位表备料行、6 条不上线物料，均已标注原因）。CY028 三份文件 119 PASS / 1 NG，那 1 条是真实差异（UR0420 与 4040）。生成器评估不变：读表 1000 份全部正确；留出生成器 400 份无误判 PASS、无误判 NG。

避免以后再误判的做法不变：每次用户报来的误判都在真实文件上复现、找到根因、按含义修正（不按文件名或料号特判），并加入测试（`core_test.dart`：固定宽度折行、替代料与不上线物料）。

## 命名与界面

- 输入改为 A-BOM（基准，必需）、B-BOM（必需）、C-BOM（可选，与 B 合并），合并侧显示为 B+C；报告、引导、说明、官网同步。演示文件改名为 `demo_A_BOM.xlsx` / `demo_B_BOM.xlsx` / `demo_C_BOM.xlsx`。
- 结果「通过 / 不一致」改为 PASS / NG（三种语言）。
- 结果表：料号列加宽并可换行显示完整料号，描述列收窄；统计卡下方的空白改放筛选栏（窗口宽度 ≥ 1250 时），行距收紧。

## 核对与输出可配置

- 设置 → 核对与输出：选择参与核对的字段（描述、用量、位号、厂商料号、厂商、替代料、贴装标记、层级、其他共有列）。关闭的字段仍用于配对，但不再比较，不会导致 NG 或需复核；结果页和报告都会写明哪些字段没有核对。
- 报告可选包含的列组（来源、描述、用量、位号、缺少/多出、其他列、来源行号、匹配依据、原因、风险、标准化参数、云端说明、AI 说明）和列出的结果（例如只输出 NG 与需复核）。
- 代码：`CompareOptions`（`bom_compare.dart`）、`ReportOptions` 与列定义表（`report.dart`）、`AppSettings.compareSkip / reportHidden / reportStatuses`。

## 多种本地模型（低配置电脑）

本地模型只为规则配不上的物料推荐候选（结果一律需复核）；不开模型时程序规则照常完整核对。候选模型在同一评估（`tool/eval_semantic.dart`：改料号、无位号、多语言的 BOM，20 份 445 行，限 4 核）上实测：

| 模型 | 文件 | 内存增量 | 256 条耗时 | 向量配对正确 | 配错 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Granite-Embedding-278M multilingual Q4_K_M（默认，推荐） | 209 MB | 336 MB | 2.6 s | 49.2% | 0 |
| Granite-Embedding-107M multilingual Q8_0（轻量） | 115 MB | 260 MB | 1.5 s | 47.9% | 0 |
| EmbeddingGemma-300M Q8_0 | 318 MB | 355 MB | 3.0 s | 51.2% | 0 |
| Qwen3-Embedding-0.6B Q8_0（原默认） | 610 MB | 709 MB | 4.2 s | 45.2% | 0 |
| multilingual-e5-small Q8_0 | 126 MB | — | — | 加载失败（本 llama.cpp 不支持该文件） | — |

40 份 1038 行（32 核）结果一致：Granite-278M 46.0%、Granite-107M 44.8%、Gemma 47.5%、Qwen3 40.6%，均无配错。

- 默认改为 Granite-278M：文件约为原来的三分之一，内存一半，更快且配对更多；完整离线安装包随之变小。
- 已下载 Qwen3 的用户不受影响：未手动选择时优先使用已在磁盘上的模型。
- 设置 → 本地模型：四个匹配模型任选其一（显示大小、内存、许可证，可下载、删除、切换使用），语言模型仍为可选。
- 所有模型都有 ModelScope / Hugging Face / hf-mirror 三个来源（已逐一验证返回 GGUF 文件和正确大小），下载后校验 SHA-256。EmbeddingGemma 按其训练方式在文本前加提示词，许可证为 Gemma 条款。
- `local_ai_real_test.dart` 对每个已下载的匹配模型验证跨语言相似度。

## 核对记录

- 每次核对完成后自动保存在设置目录 `history/<编号>/`：输入文件副本（A/B/C）及 SHA-256、模式与模型、未核对的字段、各结果数量、程序版本、逐行结果（料号、结果、原因、描述）和当时导出的完整 Excel 报告。本地模型、云端或 AI 后续完善结果时更新同一条记录。
- 核对记录页（右上角时钟图标，或设置 → 核对记录）：按文件名、料号或描述搜索全部记录并显示匹配行；展开查看文件信息和按结果筛选的逐行结果；可「重新载入并核对」（先校验文件副本的 SHA-256，被改动则拒绝）、「导出当时的报告」、删除（需确认）。
- 代码：`lib/core/history.dart`（`HistoryStore`），`lib/ui/history_page.dart`；测试：`core_test.dart`（保存、替换、搜索、校验、删除），`history_view_test.dart`（自动保存、列表、重新载入）。
