## 阶段 5：混合核对（HYBRID）

本地引擎先完整核对；只把「需复核」和「未匹配」的行按批（每批 30 行）交给云端，未匹配行附带最多 5 个候选。云端回答必须通过程序校验才生效：

- 只能引用本批给出的行和候选，否则丢弃并计数。
- 程序已确认的冲突（不一致）不会发给云端，也不会被推翻。
- 只有程序因「写法不同 / 只靠参数或语义配对」而无法确认的行，云端判为同一物料、且程序确认类别兼容、参数不冲突时才改为通过（依据记为「云端 AI 确认」）。
- 云端为未匹配行找到的对应项只会成为「需复核」，不会直接通过；未登记的替代关系不会变成认可替代料。
- 批次失败或被取消时，这些行保留本地结果并标记「云端没有回答」，状态栏说明只完成了几批。
- 隐私：可关闭发送料号原文（改用代号）、位号列表（只发数量）、其他列。

## 阶段 6：完全云端核对（CLOUD_FULL）

云端先识别两份 BOM 的字段（程序只采纳与列内容相符的结论），再分批（每批 25 行）为第一份 BOM 的每一行在另一份 BOM 中找对应行（可一对多）。程序随后：

- 检查每一行恰好被回答一次；缺答的行使整个核对标为「未完成」，界面不显示完成。
- 丢弃引用不存在的行或候选的回答；同一行被多处认领时不采用并标为需复核。
- 用自己的比较逻辑比较每一对的描述参数、用量、位号和其他列：程序发现冲突时以程序为准（云端判通过的标「云端判为通过，但程序发现冲突」）；云端判有差异而程序未确认的为需复核。
- 只有云端支持的配对（料号不同且没有共同位号）最多为需复核。
- 云端失败、截断或输出无效时没有结果可显示，提示改用本地模式；不会用本地结果冒充云端结果。

## 测试结果（本地模拟云端，未调用真实云端 API）

真实云端调用需要 API Key，目前没有；以下用本机的模拟服务器（实现 OpenAI 与 Anthropic 的 HTTP 格式）测试程序的校验是否可靠：

```
honest cloud settles lines the local engine could not;honest cloud: PASS 2341 -> 2409, false PASS 0, dropped 0;dishonest cloud: false PASS 0, dropped answers 106; | cloud-full: false PASS 0 of 1560 lines; same result as the local engine on 1544
```

- 诚实的模拟云端（知道正确答案）：混合核对把 120 组注入变化 BOM 的通过数从 2341 提高到 2409（解决了本地只能判需复核的跨语言写法），误通过 0。
- 不诚实的模拟云端（对一切都说「相同」，并引用不存在的行）：误通过 0，106 条无效回答被丢弃。
- 完全云端核对：模拟云端对所有 1560 行都判「通过」，程序的字段校验仍使真实变化没有一条通过；1544 行与本地引擎结论相同。
- 批次失败、截断、编造引用：核对均标为未完成，不显示完成。
- 应用层：混合模式完成后结果完整；云端不可用时完全云端模式没有结果并给出错误；本地模式不发出任何网络请求。
- Provider：OpenAI / DeepSeek / Anthropic 请求格式、限流重试、Key 错误不重试、Schema 不符重试后拒绝、截断、取消、超时、未填 Key 时不发请求，全部通过。
